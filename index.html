      SSDD concepts used in this app

      Security requirements

      • SR-1 Every permission starts on Deny (opt-in only).
      • SR-2 Only the four app types and the values Allow and Deny are accepted.
      • SR-3 Invalid or unknown input is rejected and fails safe to Deny.
      • SR-4 No choice is stored, logged or sent off the device.
      • SR-5 Typed text is shown as plain text and can never run as code.
      • SR-6 Permission data and scoring rules can't be changed while the app runs.

      Where each SSDD concept is applied

      Input validation
      App type, permission names and Allow/Deny values are checked against fixed allowlists in the Validator. The app name is trimmed, length-limited and pattern-checked.
      Least privilege
      All permissions default to Deny. Allowing a sensitive permission the app type doesn't need costs an extra 10 points, and the advisor flags it as high risk.
      User privacy
      Choices live only in memory in this tab. There are no cookies, no storage and no network calls, and the page's security policy blocks any request. Closing the tab erases everything.
      Secure design
      Data, validation, scoring and display are separate layers. The data is frozen (read-only), the state is private to the engine, and anything unexpected fails safe.
      Security requirements
      SR-1 to SR-6 above, each enforced in the code where the matching [SSDD:] comment appears.
